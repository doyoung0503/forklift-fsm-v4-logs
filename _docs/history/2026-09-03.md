## 2. 회전 관측량 선정 — yaw 는 쓸 수 없다

`rotation_fit/compare_signals.py`

회전 세그먼트 14개에서 정지→정지 변화량을 비교:

```
관측량                                 명령방향 부호일치   비고
─────────────────────────────────────────────────────────────────────
yaw_deg (전면평면 PnP yaw)             8 / 14            좌/우 부호가 뒤집힌 로그 존재
bearing = atan2(pos_x, pos_z)          14 / 14           정지구간 표준편차 0.01~0.40 deg
```

- `corr(Δyaw, Δbearing) = -0.12` — 두 신호가 사실상 무관하다.
- 회전 중 `|p| = hypot(pos_x, pos_z)` 가 보존된다 (Δ|p| = 0.00~0.04 m, 최대 0.33 m).
  → 유효 회전중심이 카메라 광학중심 부근. `CAMERA_TO_ROT_CENTER_Z_M = -0.80` 은 근거가 약하다.
- 따라서 **회전각 관측량 = 전면중심 방위각 변화량** 으로 정의했다. 이 값이 FSM 의
  FACE/RECENTER 모드가 실제로 쓰는 오차신호와 같다.


핵심: **STOP 명령에도 수송지연 T_off 가 있다.** 이것이

```
정지 yaw_sd  중앙값 [deg]              0.231       0.255
```

## 9. 9점 pose 로 적합 재수행 + 최종 확정

### 9.1 4점 pose 의 결함이 회전 적합의 상류 원인이었다 [확인]

`rotation_fit/compare_pose_methods.py` (같은 키포인트 덤프, 12 회전 세그먼트):

```
방법     정지 yaw sd   Δyaw 명령방향 부호일치   corr(Δyaw, Δbearing)   기울기
──────────────────────────────────────────────────────────────────────────────
4pt      0.204 deg     7 / 12                   0.020                  0.018
multi    0.230 deg     12 / 12                  0.987                  0.709
```

- 2절에서 "yaw 는 못 쓴다" 고 결론냈던 것의 원인은 **전면 4점 평면 PnP** 였다.
  9점으로 바꾸니 yaw 가 회전량 관측값으로 복구된다.
- 기울기 0.709 는 회전중심이 카메라 뒤 d 에 있으면 설명된다:
  `Δbearing = Δheading·(r+d)/r`. 세그먼트별 r 을 반영해 적합 → **d = 1.05 m**
  (3d-expert 의 독립 추정 0.87 ± 0.47 m 과 일치).
- **2절의 "회전중심이 카메라 근처" 결론은 틀렸다.** |p| 보존 검정이 d=0 과
  d=0.8 을 구분할 만큼 민감하지 않았다(예상 차이 0.03 m vs 잡음 0.02~0.05 m).
  9점 yaw 가 생기고 나서야 판별이 됐다.

### 9.2 파이프라인 확장

- `rot_common.py` 에 `POSE_SOURCE`(log / recomp4 / recompmulti) 와
  `ANGLE_SIGNAL`(bearing / yaw) 스위치 추가. `run_all.py` 가 4 조합을 돌려 비교.
- **정렬 게이트 추가**: 재추론 소스는 4점 재계산을 원본 로그와 대조해
  |Δx| 중앙값 > 5 mm 이면 그 녹화를 버린다. `20260901_175419` 가 걸러졌다 —
  moovless 복구 파일이라 중간 프레임이 유실돼 고정 offset 이 성립하지 않는다.
- **검출기 견고화**(재추론은 표본이 2배라 기존 임계가 오검출):
  - 온셋: 임계 통과 후 0.5 s 안에 2×임계 도달 + 그 사이 0.5×임계 유지 확인
  - 정지: `all()` → 이후 표본의 95% 가 밴드 안 (뒤쪽 단일 이상치가 정지시각을
    몇 초씩 밀어내던 문제)
- **시뮬레이터 벡터화**: 모델 A/B 모두 구간별 해석해로 교체. LOO 교차검증이
  ~100배 빨라졌고, `rotation_model.py` 의 독립 구현과 5자리까지 일치(교차검증).

### 9.3 도메인 선택과 최종 파라미터

지연(T_on/T_off)은 구동계 성질이라 도메인 무관인데, yaw 는 bearing 보다 잡음이
7배 커서 T_on 이 늦게 치우치며 w_max 와 맞바꿔진다. 그래서 **지연은 bearing
적합값으로 고정하고 각속도만 yaw 로 적합**했다.

```
source                  n   T_on   T_off  alpha   w_max   traj_rms  total_rms  loo_rms
──────────────────────────────────────────────────────────────────────────────────────
log_bearing            11  1.118   0.368  23.76   13.51     1.086      1.348    1.618
recomp4_bearing        10  1.092   0.374  22.69   12.99     1.088      1.379    1.698
recompmulti_bearing    10  1.082   0.352  21.94   14.66     1.239      1.641    2.004
recompmulti_yaw         9  1.282   0.347  26.75   11.34     1.125      1.434    1.844
recompmulti_yaw_fixed*  9  1.082   0.352  13.06   12.01     1.134      1.437    1.814  <- 채택
```

**변환 검증** — heading 모델 하나에 기하 변환만 적용해 bearing 회전량을 재현:

```
d [m]     bearing 총회전각 편향     RMS
──────────────────────────────────────────
0.0              -3.50            3.92
0.8              -0.82            1.77
1.0              -0.15            1.64   <- bearing 직접 적합(1.64)과 동일
1.3              +0.85            1.98
```

d=1.0 m 에서 직접 적합과 같은 정확도 → heading 모델 하나로 두 도메인 커버 가능.
d=0 은 명확히 기각(9.1 의 오류 정정을 데이터로 확인).

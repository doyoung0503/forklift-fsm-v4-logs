# 별도 FSM 프로세스와 모델 결과 시뮬레이션 검증

2026-09-07 작업공간의 현재 FSM을 별도 프로세스로 실행했다. 카메라와 추론 런처를 실행하지 않았으며, 가상 모델 결과를 공급하고 실제 가상 CAN 수신으로 차량을 움직였다. FSM 소스 ID는 `e259c9bbf5204a40bf6c00d1aaf6977bf17746d4a30594a201621b158ef828de`이다. 실행별 소스·시뮬레이터 해시는 validation.json에 기록되어 있다.

## 기준 54조건

X=-0.3/0/+0.3m, Z=1.8/2.0/2.2m, yaw=-15/0/+15°의 27조합을 oracle/fov에서 각각 실행했다. 모델 출력 30Hz, 지연 0.12s, 포즈 오차와 확률 미탐 0, HFOV 55°, 가시 비율 기준 50%, 독립 차량 프로필, STOP 후 관성 0이다. 화면의 임의 Gaussian 초기값(10Hz, 비영 표준편차·미탐률)과 구분한다.

| 결과 | oracle 27조건 | fov 27조건 |
|---|---:|---:|
| FSM DONE | 21 | 21 |
| FSM FAILED | 6 | 6 |
| 외부 삽입 판정 통과 | 7 | 7 |
| 포크 기하 충돌 | 14 | 14 |
| 정렬 회전 후보 없음 | 6 | 6 |
| 재입력 비교 프레임 | 27,994 | 27,994 |
| 비교 CAN 프레임 | 101,548 | 101,548 |

총 55,988개 실행 프레임 및 203,096개 CAN 프레임을 새 FSM 프로세스에 재입력하여 일치했다. 일부는 모델 결과 사이의 가상 타이머 스텝이므로 실행 프레임 수와 추론 결과 프레임 수는 다르다. 검증 통과율은 위 가정에 대한 결과이며 실차 성공률이 아니다.

## 최신 FSM의 비전 독립 삽입

현재 원본은 정렬 승인 후 수락한 거리를 전진 피팅식의 시간으로 바꾸어 한 번 전진한다. READY_TO_INSERT/INSERT_DRIVE/INSERT_SETTLE에서 `vision_independent=True`이며 실차 런처가 포즈 없이 step을 호출한다. 시뮬레이터도 같은 호출을 최대 10ms 가상 간격으로 수행한다.

정면 X=0, Z=2m, yaw=0°에서:
- 약 2.333s: READY_TO_INSERT
- 약 2.343s: INSERT_DRIVE
- 약 9.853s: INSERT_SETTLE / STOP
- 약 11.853s: DONE
- 종료 카메라 Z 약 0.29855m, 목표 잔여 0.30m. 기준 판정 통과.

그래서 현재 기본 54조건에서는 삽입 중 시야 상실이 복구 timeout으로 바뀌지 않는다. 접근 단계의 포즈 상실 처리는 그대로 유지된다. Z=5m, 강제 미탐 시작 4s / 기간 5s 실험에서는 STANDOFF_MOVE → RECOVER_VISUAL → FAILED(PnP recovery timeout)가 발생한다.

시간 제어에서 FSM DONE은 실제 이동 거리의 센서 검증을 의미하지 않는다. 전후진 배율 0.8이면 정면 조건에서 약 0.339m의 미삽입 잔여가 남고, 배율 0이면 FSM은 DONE이어도 실제 잔여가 1.7m다. 시뮬레이터는 이를 별도의 삽입 실패로 판정한다.

## 회전·충돌 조건

X=+0.3m/yaw=-15° 또는 X=-0.3m/yaw=+15°의 각 Z 조건에서는 실행 가능한 정렬 회전 후보가 없어 실패했다. 원본 후보 탐색과 제약의 결과이며 모든 가능한 차량 경로의 불가능성을 증명하지 않는다.

포크 충돌은 연속 개구부 0.71m, 포크 외측 0.60m, 개별 포크 폭 0.10m, 팔레트 깊이 1.10m의 평면 기하로 검사한다. 충돌을 원본 FSM에 강제 STOP으로 주입하지 않으므로 접촉 이후 궤적은 실제 접촉력 반응을 나타내지 않는다.

## 프로세스·인터페이스 검사

Python 검사 43개와 JavaScript 검사 5개가 통과했다. 다음을 포함한다.

- 부모 서버에 calib/카메라/추론 모듈이 없고 실제 다른 PID에서 FSM 실행.
- 별도 프로세스와 비교용 직접 실행의 상태·CAN 프레임·최종 차량 상태 일치.
- 프레임 간격·지연 변동과 Gaussian 오차가 있는 입력의 재현.
- 실차 ui/diagram_v4.py에서 읽은 5단계 정의·활성 단계 표시.
- 모델 5Hz에서도 비전 독립 삽입의 10ms 타이머 호출 유지.
- 예외 종료, 응답 지연, 잘못된 JSON·응답 번호를 장애로 판정하고 프로세스 회수.
- 프로세스 유실 시 가짜 STOP 없이 CAN watchdog/관성에 따른 정지.
- 정상 시간 제한에서 원본 STOP 프레임 전송과 재현.
- 다른 종료 상태명과 내부 진단 속성이 없는 대체 제어기의 lifecycle 처리.
- 새 프로세스에서 저장된 코드 반영 및 기존 프로세스의 버전 유지. 파일 크기·수정 시각이 같은 변경도 확인.
- 세션별 PID·설정 분리, 종료 회수, 고정 10×10m 뷰와 초기 월드 배치 좌표 변환.

현 어댑터에는 원본 클래스/step, 가상 시계, control.py 내부 송신 경로의 의존성이 남아 있다. 이 의존성은 자식 안에만 있으며, 실제 장비의 CAN 스레드 지터나 유압 구동을 재현하지 않는다.

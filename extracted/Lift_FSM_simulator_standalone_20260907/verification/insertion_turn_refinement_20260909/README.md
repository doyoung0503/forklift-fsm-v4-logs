# 삽입 정렬 회전 후보 세분화

2026-09-09. 실제 FSM과 시뮬레이터가 함께 사용하는
`depth_cam/calib/fsm_v4/planner.py::insertion_alignment_turn`에 적용했다.

기존 후보를 먼저 검사하고, 모두 실패할 때 각 후보 사이를 절반씩 나눠 검사한다.
양 끝이 모두 실패한 구간도 내부를 검사한다. 각 단계에서 기하/목표 yaw/시야를
통과한 후보가 있으면 기존 우선순위(작은 회전량, 여유)로 선택한다.
없으면 다시 나누되 구간 폭0.05도 이하에서 종료한다. 이진 세분화이므로 실제
추가 후보는3.75,4.25,5.9375도 등이며 일정0.05도 격자로 반올림하지 않는다.

설정 `INSERT_TURN_REFINE_RESOLUTION_DEG=0.05`는 탐색 해상도다.
실제 최소 명령각 `INSERT_FINE_MIN_TURN_DEG=0.5`는 유지한다. 이보다 작은
각도를 새로 실행하지 않는다. 일반 waypoint 후보 생성은 변경하지 않았다.
기존 후보가 유효하면 결과도 그대로 유지한다. 좁은 모든 연속 구간을 발견한다는
보장은 없으며, 설정된 해상도까지의 유한 탐색이다.

선택한 각도는 기존 `_begin_rotation`과 fitted response를 거쳐 CAN 명령
유지시간으로 변환된다. 회전 STOP은 기존 CAN TX 타이머가 담당하고, 정착 후
관측 포즈로 삽입 가능 여부를 다시 확인한다. 코드 변경이 실차에도 적용되지만
실차 시험은 수행하지 않았다.

## 검증

- 단위/회귀72개 통과: 세분화6, 기존 삽입/회전/adaptive/초기보정 경계 등61,
  CAN 타이머5. 저장 실패 포즈의 좌우, 양 끝과 첫 중간값도 실패하는 좁은 구간,
  시야 거절, 기존 후보 유지, 종료 횟수, 설정 검증을 포함한다.
- 가상 CAN과 실제 FSM으로6개 시나리오 모두 DONE/success. 초기보정과 추가
  구동오차 및 전진 선행 STOP은 꺼서 일반 접근의 세분화 동작을 검사했다.
- 5m/L±0.91125: 이전 후보 누락 실패가 해결됐다. 더 이른 정지 포즈에서
  ±5.75도 삽입 정렬을 선택해 완료했다. 이전 마지막 실패 포즈만 검사하면
  ±3.75도 후보를 찾는다.
- 3m/L±0.30: ±4.25도 정렬 후 완료. 5m/L1.0125:5.9375도 정렬 후 완료.
  3m/L0: 회전 없이 완료.

실행 설정, source/simulator hash, 이벤트, 최종 포즈는 [summary.json](summary.json)에
보존했다. 초기보정 레터럴 기준식은 이번에 변경하거나 재측정하지 않았다.
기존 시뮬레이터 충돌 검사는 제거된 상태다.

재시작한 `main_rec_v4.py`와 새 시뮬레이터 세션에 반영된다.

# 재측정 탐색 실패 원인 — 2026-09-09

후속 사용자 요청으로 시뮬레이터 자체 충돌 검사는 제거했다. 아래는 제거 전
저장 결과의 원인 조사다. FSM의9블록 검사와 회전 후보 탐색은 변경하지 않았다.
제거 후D3/L0.28125와D5/L0.855625는 성공하며D5/L0.91125는 후보 누락으로
여전히 실패한다. [제거 후 재실행 결과](../simulator_collision_removed_20260909/summary.json).

201개 검색 표본 중 실패 76개: 독립 충돌 판정 26개, waypoint 후보 없음 50개.
초기보정 OFF, 추가 오차 0인 저장 결과를 조사했다. 런타임은 변경하지 않았다.

## 1. 충돌 형상이 서로 다름

FSM은 1.10m 팔레트의 0.20m 블록 9개와 0.25m 간격을 검사한다.
시뮬레이터 `Plant.check_collision`은 전 깊이에 걸쳐 폭0.71m인 연속 통로를
가정한다. 따라서 블록 사이의 빈 공간에 나온 포크도 연속 벽 충돌로 판정한다.

충돌 26개 모두 저장된 삽입 승인 포즈에서 nine-block 검사를 통과했다.
실제 종료 위치까지 이동량을 연장해 검사해도 26개 모두 통과했다.
반대로 추가 이동 없이 명목 목표 카메라Z=0.30m까지만 계산해도 연속 통로
검사에서는 26개 모두 충돌한다. 이번 충돌군의 직접 원인은 추가 구동오차나
회전 STOP 지연이 아니라 검사 형상 불일치다.

최초 충돌 지점의 포크 외측 끝 깊이는 0.804~0.847m다. 실제 설정상 이 깊이는
중간 블록 끝0.65m와 뒤쪽 블록 시작0.90m 사이의 빈 공간이다.

예: D3/L0.28125는 FSM DONE, 최종 yaw4.8558도. 최초 충돌 좌표는
팔레트 기준(-0.355022,0.839192)m이고 연속 통로 왼쪽 경계는 -0.355m다.
최종 연속 벽 침범량은1.345mm, 명목 목표에서도1.187mm다.
D5/L0.855625도 동일 원리이며 최종 침범량2.483mm다.
이는 설정된 평면 블록 형상에 대한 판별이고 실제 차량 충돌 시험은 아니다.

## 2. 회전 후보 간격과 단계 선택이 결과를 불연속적으로 바꿈

삽입 회전은 기본0.5도 간격의 유한 후보와 일부 정확한 목표각 중에서 고른다.
가능한 각도 구간이0.5도보다 좁으면 그 사이를 놓칠 수 있다.
아래 구간은 저장 truth에서0.01도 간격으로 재계산한 기하 표본이며,
구간 전체에 대한 시야/실행 검증은 아니다.

| 초기 D/L | 검사 포즈에서 기하적으로 가능한 회전 | 기존 후보 | 결과 |
|---|---|---|---|
| 3m / 0.28125m | 4.00~4.41도 | 4.0도 | 즉시 삽입 승인 → 연속 통로 충돌 판정 |
| 3m / 0.30m | 4.08~4.42도 | 없음 | 근거리 추가 전진0.419m → 이후5도 회전 → 성공 |
| 5m / 0.91125m | 3.57~3.91도 | 없음 | 삽입 회전 못 찾고 추가 전진도 제한 → 실패 |
| 5m / 1.0125m | 3.90~4.07도 | 4.0도 | 삽입 성공 |

5m/L0.91125를 현재 FSM에서 초기보정 OFF로 재실행했고 전체 trace hash가
측정 당시와 정확히 일치했다. 그 마지막 포즈에서3.7도는 nine-block 검사와
실제 관측 metadata를 사용한 회전 시야 검사를 모두 통과한다.
3.5도는 중간 블록과 충돌,4.0도는 전면 포켓 여유 부족으로 거절된다.
최소 미세 회전각만 낮춰도 3~4도대 후보 격자가 자동으로 촘촘해지지는 않는다.

## 3. 전진 공간 제한과 포괄적인 오류 문구

같은5m/L0.91125의 마지막 횡오차는0.251746m, staging까지 남은 정상 거리는
0.194486m다. `_maximum_staging_safe_forward_m`은 횡오차가0.10m보다 크면
staging 앞0.20m의 조정 공간을 남기므로 전진 허용량이0이 된다.
따라서 작은 삽입 회전을 놓친 뒤 전진으로도 빠져나갈 수 없다.

재실행 후보73개 중60개는 회전 시야에서 제외됐고, 시야를 통과한13개도
staging 전진 제한0으로 탈락했다. 즉 이 사례의 직접적인 막힘은 시야만이
아니다. 현재 planner는 후보가 비면 모두
`no rotation+forward action restores safe horizontal/vertical visibility`를
반환하므로 실제 거절 이유가 로그에서 구분되지 않는다. 다른49개 planner
실패의 개별 탈락 사유까지 분해한 것은 아니다.

## 의미와 후속 수정 순서

기존 측정 경계는 서로 다른 두 형상 검사를 동시에 통과한 경계이므로
실제 nine-block 형상의 순수한 보정 한계로 해석하면 안 된다.
현재 적용 수식 안쪽의 검사 표본은 통과했지만, 그것만으로 형상 불일치나
후보 누락이 해결되었다고 볼 수 없다.

우선 독립 시뮬레이터 충돌 형상을 실제9블록으로 맞추고, 좁은 삽입 회전
구간을 세밀하게 탐색하며, 후보 탈락 사유를 시야/공간/최소이동으로 나눠
기록하는 것이 적절하다. 이 수정 뒤 기준을 다시 검증해야 한다.
원인 조사 시점에는 런타임을 수정하지 않았고, 이후 자체 충돌 검사 제거를
별도 요청에 따라 적용했다. 회전 후보 세분화와 오류 문구 수정은 미적용이다.

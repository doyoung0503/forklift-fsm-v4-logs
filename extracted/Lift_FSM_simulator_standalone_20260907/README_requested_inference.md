# FSM 요청 기반 시뮬레이션

브라우저 Run/Step과 `process_runtime.Session`의 기본값은 `inference_mode="requested"`입니다.

1. 팔레트와 리프터의 초기 배치를 설정하고 Run을 누릅니다.
2. 별도 `main_rec_v4.py --mode simulation --ipc` 프로세스에서 실제 `CalibrationFSMV4`와 네이티브 FSM 창을 실행합니다.
3. 실제 런처처럼 FSM의 `skip_detection` / `vision_independent`가 꺼져 있으면 추론을 요청합니다. 요청 시점 GT를 저장하고 XYZ/yaw별 독립 정규분포 오차를 한 번 샘플링합니다.
4. `max(0, Normal(latency, latency_sd²))`초의 가상 시간이 지난 뒤 `GT(request_time) + error`를 반환합니다. 첫 결과도 지연 전에는 전달하지 않습니다. 동시에 하나의 요청만 처리하며 `model_hz`는 요청 최대 빈도입니다. 지연이 길면 실제 결과 FPS는 낮아집니다.
5. 실제 FSM이 결과로 판단하고 원본 CAN 프레임을 생성합니다. 차량은 CAN ID/바이트만 받아 움직입니다. 영상 없이 동작하는 구간에서도 CAN과 가상 시간은 진행하며 새 모델 요청은 발생하지 않습니다.
6. FSM 창 좌측 상단 640×480 영역에는 현재 GT의 3D 카메라 렌더링과 FSM에 전달한 동일 결과의 오버레이를 표시합니다. 지연 중 배경은 현재 위치를 반영하고 마지막 수신 결과를 유지합니다. 영상 비사용 구간의 오버레이 생략 규칙은 실제 프로그램과 같습니다.

화면 지연 기본값은 평균 **0초**, 표준편차 **0.05초**입니다. 음수 표본은 0으로 제한하므로 약 절반이 0초이며 평균·표준편차를 모두 0으로 설정하면 지연이 없습니다. 실험용 값이며 측정값이 아닙니다. API 생략 기본 지연은 기존 호환값 0.12초/표준편차 0초이므로 UI와 같은 실험에는 값을 명시하세요. Pause/Step은 벽시계가 아니라 가상 시간을 제어합니다.

원본 FSM의 상태 전이·안정화·정지 대기·실패 판정을 사용합니다. 네이티브 창은 시뮬레이션 전용 표시 어댑터입니다. 실제 카메라/모델 로딩, 물리 CAN 초기화, 실장비 유압 초기화와 키보드 디버그 게이트는 이 경로에 포함되지 않습니다.

이전 결과 비교에는 명시적 `inference_mode="continuous"`를 사용하세요. 독립 `protocol_world.World`도 종전의 주기적 출력/과거 GT 참조 방식을 유지합니다. 요청 기반 환경은 `RequestedWorld`이며 GT는 렌더링에만 사용하고 FSM 입력은 오차가 적용된 모델 패킷으로 제한합니다.

실행: `run_v4_simulator.bat` → 브라우저에서 초기 배치 적용 → Run.
검증: `python -m unittest discover -s tests -p "test_*.py"`.
